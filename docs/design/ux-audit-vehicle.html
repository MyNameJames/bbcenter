📝 ฟอร์มจองมี 8 fields — Cognitive Overload
Critical
ผู้ใช้เห็น field ทั้งหมดพร้อมกัน: วันที่, เวลา, ปลายทาง, วัตถุประสงค์, จำนวนผู้โดยสาร, คนขับ, join_allowed, expense_type — มากเกินไปสำหรับ primary task
💡 Fix: Progressive Disclosureแบ่งเป็น 2 step — Step 1: วันเวลา + ปลายทาง. Step 2: รายละเอียดเพิ่มเติม. ลด mental model load ลง ~40%
⏳ ไม่มี Feedback หลัง Submit
Critical
หลัง submit การจอง ผู้ใช้กลับไปเห็นปฏิทิน แต่ไม่รู้ว่าอนุมัติเมื่อไหร่ ไม่มี estimated time, ไม่มี "การจองรอ N รายการ" summary — Zero State ที่ไม่สมบูรณ์
💡 Fix: Confirmation Stateแสดง inline card "รอการอนุมัติ" พร้อม status tracker mini ใน calendar cell ทันที
🖱️ Drag-to-Merge มี Zero Discoverability
High
Feature รวม trip ด้วย drag-and-drop เป็น power feature แต่ผู้ใช้ใหม่ไม่รู้ว่ามี — ไม่มี affordance, tooltip, หรือ empty state guide ใดๆ
💡 Fix: Onboarding Tooltipครั้งแรกที่ admin เข้าหน้านี้ แสดง tooltip "ลาก card เพื่อรวม trip" พร้อม dismiss
📱 Mobile: ปฏิทินยุบเป็น List แต่ UX ไม่ต่อเนื่อง
High
บน mobile มี mobile-list-header แยกต่างหาก แต่ปุ่ม "ไม่มีรายการ" ถูกใช้เป็น booking trigger — ทำให้ mental model สับสน ระหว่าง list และ action
💡 Fix: Bottom Sheet + FABใช้ Floating Action Button (FAB) สำหรับ "+ จองรถ" แยกออกจาก list header ให้ชัดเจน
🔁 Page Transition ไม่ฟุ่มเฟือย — ✅ ดีแล้ว
Good
การใช้ Modal-first design ช่วยลด page reload ได้ดีมาก ผู้ใช้จองได้โดยไม่ต้องออกจากปฏิทิน — สอดคล้องกับ Apple HIG principle "Minimize navigation depth"
✅ Keep: ตรงนี้ถูกทางแล้ว ไม่ต้องเปลี่ยน ระวังอย่า refactor ให้กลายเป็น multi-page
🧭 Sidebar Structure ชัดเจนดี — ปรับเล็กน้อย
Minor
Section labels "MENU" / "SERVICES" / "ADMIN" ชัดเจน แต่ "SERVICES" รวม Dashboard + Repair + Room ซึ่ง Mental Model ไม่ตรง — Dashboard ไม่ใช่ "service"
💡 Fix: เปลี่ยน "SERVICES" → "OTHER" หรือแยก Dashboard ขึ้นไปเป็น section แรกก่อน MENU
🚗 Driver Flow กระชับและตรงประเด็น — ✅
Info
driver_home.html เน้น task ของวันนี้เป็นหลัก ไม่มี information overload — เหมาะกับ driver mental model ที่ต้องการ "วันนี้ทำอะไร" ทันที
✅ Keep: Flow นี้ถูกต้องตาม Google Material "Task-oriented design" — ไม่ต้องปรับ
⚡ Notification Poll 60 วินาที — Perceived Slowness
High
Notification bell poll ทุก 60 วินาที ผู้ใช้อาจรออนุมัติ แล้วเห็น bell update ช้า ทำให้รู้สึกว่าระบบช้า — เป็นปัญหา Perceived Performance
💡 Fix: ลด poll เป็น 20–30 วินาที หรือ refresh bell ทันทีเมื่อ user กลับมา focus window (Page Visibility API)
2 Layout Density — ควรลดอะไรบ้าง?

วิเคราะห์ visual weight และ information hierarchy — ระบุส่วนที่ซ้ำซ้อนหรือหนาเกินไป

Component ปัญหาที่พบ (Before) แนวทางปรับปรุง (After)
Calendar Header
Toolbar + Month nav		 Issue Month nav อยู่ทั้งใน header bar และ toolbar ซ้ำกัน 2 จุด — เปลือง vertical space 65+50px Fix รวมเป็น 1 row เดียว: ← ชื่อเดือน → + ปุ่ม "วันนี้" + ปุ่ม "+ จอง" ทั้งหมดใน header bar เดียว
Calendar Cell
min-height: 110px		 Issue Cell สูง 110px ทำให้ calendar ต้อง scroll บน laptop 1080p — information density ต่ำเกินไป Fix ลดเป็น 80–90px แสดง event แค่ 2 รายการ + "+N more" link — compact แต่ยัง scannable
Booking Modal
8 fields พร้อมกัน		 Issue แสดง field ทั้งหมดในครั้งเดียว รวมถึง expense type ซึ่งเป็น advanced option ที่ไม่ใช่ทุกคนใช้ Fix แยก 2 ส่วน: Essential (4 fields) + ▸ "ตัวเลือกเพิ่มเติม" collapsible สำหรับ advanced options
Admin Card
booking-card		 Issue Card แต่ละใบมี padding 14px + border-radius 12px + shadow ซ้อนกัน ทำให้หน้า admin ดู heavy Fix ใช้ table-row สำหรับ list view ปกติ เปลี่ยนเป็น card เฉพาะ mobile หรือ card view mode
Commented Code
vehicle.html L81–104		 Issue มี block code ที่ comment ออกแต่ยังอยู่ในไฟล์ (budget display, progress bar) เป็น "dead weight" ใน HTML Fix ลบออกหากไม่ใช้ หรือ move ไปไว้ใน feature branch — ไม่ควรอยู่ใน production template
Sidebar Footer
Logout button		 Issue Logout อยู่ด้านล่าง Sidebar เพียวๆ ไม่มี user avatar / ชื่อ ทำให้ไม่รู้ว่า login เป็นใคร Fix เพิ่ม user avatar + ชื่อ + role ใน sidebar footer เหมือน Notion/Linear ก่อน logout link
Font Icon Sets
FontAwesome + Bootstrap Icons		 Issue โหลดทั้ง FontAwesome และ Bootstrap Icons ในทุกหน้า — render blocking 2 icon libraries เพิ่ม load time Fix เลือก 1 library (แนะนำ Bootstrap Icons — เบากว่า) และ standardize ทั้งโปรเจกต์
💡 Key Insight — Visual Hierarchy: ปัญหาหลักของ layout คือ ทุก element มี visual weight เท่ากัน — card, button, badge, border ต่างใช้สีเข้มและ shadow ใกล้เคียงกัน ผลคือ eye ไม่รู้จะ focus ที่ไหน แก้ด้วยการ establish clear hierarchy: Primary action 1 จุด, Secondary muted, Tertiary text-only

🎨 Indigo + Purple ขัดกันใน same page
Critical
ปัจจุบันใช้ Indigo (#4F46E5) และ Purple (#8B5CF6) พร้อมกัน ซึ่งเป็นสี analogous ที่ใกล้เคียงกันมาก ทำให้ยากที่จะแยกว่า Indigo = Primary หรือ Purple = Primary
💡 Fix (Navy+Amber): Navy (cool dark) + Amber (warm light) เป็น complementary contrast ที่แยกกันชัดเจน — sidebar navy, CTA amber = instant visual anchor
🌊 Page bg #F0F2F8 (Lavender) รบกวน Indigo
High
Background มี purple tint (#F0F2F8) ทำให้สีรวมทั้งหน้าดู "ม่วงหมด" — เมื่อรวมกับ sidebar indigo, hover purple, badge purple ทำให้ accents หายไปในสี
💡 Fix: เปลี่ยน page bg เป็น neutral #F0F3F9 (Navy-50 ที่ cool แต่ไม่ม่วง) — card จะ pop ขึ้นมาบน bg ได้ชัดขึ้น
4 Priority Matrix — ทำอะไรก่อน?

จัดลำดับตาม Impact × Effort — เริ่มจาก Quick Wins ก่อน

P1 — ทำเดี๋ยวนี้ (High Impact / Low Effort)

  • เปลี่ยน page bg จาก #F0F2F8 → #F0F3F9 (neutral)
  • รวม month nav header ซ้ำ 2 จุดให้เหลือ 1 แถว
  • เพิ่ม user avatar + ชื่อใน sidebar footer
  • ลด notification poll จาก 60s → 20s
  • ลบ commented-out code block ใน vehicle.html

P2 — Sprint นี้ (High Impact / Medium Effort)

  • ปรับ color system เป็น Navy/White/Amber tokens
  • Modal form: แยก Essential / Advanced sections
  • ลด calendar cell height จาก 110px → 85px
  • เพิ่ม onboarding tooltip สำหรับ drag-to-merge
  • เปลี่ยน icon library ให้ใช้แค่ 1 set

P3 — Sprint ถัดไป (Medium Impact / Medium Effort)

  • Mobile: เพิ่ม FAB button แทน mobile-list trigger
  • Confirmation state หลัง submit booking
  • Admin: ใช้ table row แทน card สำหรับ list view desktop
  • เปลี่ยน "SERVICES" label ใน sidebar

P4 — Backlog (Low Impact / High Effort)

  • Progressive Disclosure booking modal (2-step wizard)
  • Page Visibility API for notifications
  • Full design token migration ทุกไฟล์
