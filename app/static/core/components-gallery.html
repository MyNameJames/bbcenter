shell macro (ไม่มี Python class — เหมือน bb_table shell). control ที่ JS track: [data-filter-group] (+[data-multi] = เลือกหลายค่า) ใช้กับปุ่มที่มี data-value (active = .is-on) · หรือ <select name>/<input name>. default = ค่าตอนโหลด · ออกจาก default = active (badge dot แดง) · ล้าง = คืน default. ไม่มีปุ่มยืนยัน — ทุกการเปลี่ยน dispatch bb-filter:change ทันที.
ปุ่ม "ล้าง" (data-bb-filter-clear) รู้จักแค่ [data-filter-group] chip/seg + <select name>/<input name> ธรรมดา — reset กลับไป snapshot ตอน init เท่านั้น. ไม่รู้จัก widget ที่มี state ภายในตัวเอง เช่น bb_slider (dual-handle) หรือ bb_daterange: widget พวกนี้ผูก hidden input ไว้ก็จริง แต่ตำแหน่ง handle/ปฏิทินเก็บเป็น JS state แยก (vals / appliedStart-End) ไม่ sync อัตโนมัติเมื่อ hidden input ถูกแก้จากนอก widget → ถ้าฝัง slider/daterange ไว้ใน bb_filter ต้อง bridge เอง: ฟัง click [data-bb-filter-clear] แล้วยิง custom event ให้ widget reset ตัวเอง เช่น slider.dispatchEvent(new CustomEvent('bb-slider:reset')) — ตัวอย่างจริงดูที่ vehicle_mileage.js (bindFilterClear).
Reload (F5) แล้ว filter ไม่กลับ default — ต้องทำครบ 3 จุด ไม่งั้นค้างค่าเดิม (เจอจริงหน้า mileage admin 2026-07-02):
1. AJAX filter ห้าม history.pushState query string ของ filter เข้า address bar — ไม่งั้น F5 จะโหลด URL เดิมที่มี query ค้าง server เลย render filter เดิมกลับมา (ดู runFilter() ใน vehicle_mileage.js ที่ตัด pushState ออก)
2. hidden input ที่เก็บ filter state ใส่ autocomplete="off" (ดู bb_slider macro) — กันบาง browser restore ค่าฟอร์มทับตอน manual reload
3. widget JS ต้องอ่านค่าเริ่มต้นจาก element.getAttribute('value') ไม่ใช่ element.value — เพราะ browser restore ทับที่ property เท่านั้น ไม่แตะ attribute ที่ server render สดทุกครั้ง (ข้อ 2 อย่างเดียวไม่พอ — ดู bb-components.js initSlider() และ bb-daterange.js enhance())
ฝั่ง server เองก็ต้องมี default fallback (เช่น เดือนนี้ถึงปัจจุบัน) เมื่อไม่มี query ส่งมาด้วย ไม่งั้น reset แล้วว่างเปล่า
